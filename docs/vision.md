# Система виженов M4T (research, только чтение)

Карта системы восприятия/вижена Matrice 4T по DUML. Данные: USB-захваты
(`idle.pcap`, полный Assistant-флеш, downgrade), подписанный манифест
`16.01.0006`, живой `probe` на **двух бортах** 2026-10-05 и публичный диссектор
dji-firmware-tools. Железо не трогали. **Серийники и координаты здесь не
приводятся** — только структура. `[C]` — подтверждено (видно на шине / в
манифесте / в публичной раскладке), `[c]` — кандидат (вывод).

## Главный вывод

Хост владеет **одной** трубой — USB к Ambarella-SoC (VID 2CA3, интерфейс MI04,
EP 0x04/0x85). DUML на ней и заканчивается. Почти вся система виженов живёт
**за полётным контроллером** на внутренней шине и с хоста не адресуется. **[C]**

## 1. Что достижимо по DUML (`probe`, 2 борта)

Отвечают 8 из 16 кандидатов, одинаково на обоих бортах:

| Адрес | Тип | Version `00/01` | Serial `00/51` |
|---|---|---|---|
| `0300` | flight controller (3) | да; поле `hardware` — **серийник борта** `[C]` | **да** — `00/51` сел. `0x04` = серийник борта `[C]` |
| `0400` | gimbal (4) | да | не отвечает на `00/51` `[C]` |
| `1100` | battery (11) | да; `hardware` — тег поставщика ячеек (`…PTL`) | не отвечает на `00/51` `[C]` |
| `0801` | Ambarella SoC (8/1) | да | отвечает, но пусто (`0xd6`) `[C]` |
| `0802` | Ambarella SoC = upgrade center (8/2) | да | отвечает, но пусто `[C]` |
| `0803` | Ambarella SoC (8/3) | отвечает | **да — 3 серийника** по сел. `0x01/0x02/0x04` `[C]` |
| `1804` | binocular/vision (18/4) | **да (queryable!)** | не отвечает на `00/51` `[C]` |
| `3100` | sentinel/FC-aggregate (31) | да; `hardware` — модельная строка | отвечает, но пусто `[C]` |

Активный probe **поправил пассивный вывод**: по захватам казалось, что `1804`
только пушит `03/ce` и «не отвечает», но вживую он **отвечает на Version
Inquiry** (серийника, впрочем, не даёт). Это и есть ценность живого discovery.

**Энумерация селектора `00/51` (`serial-scan`, live M4T).** `00/51` берёт
байт-селектор, выбирающий, чей серийник вернуть (Assistant шлёт `0x01` на `0x28`,
`0x04` на `0x68`). Полный свип `0x00…0xFF`: **`0803` — серийный хаб, отдаёт 3
серийника** — сел. `0x01` (похоже камера/оптомодуль `[c]`), `0x02` (14-значный
компонент `[c]`), `0x04` (= серийник борта с 4-символьным префиксом `[C]`);
**FC `0300`** отдаёт серийник борта на сел. `0x04` (то же «ядро», без префикса)
`[C]`; `0801/0802/3100` отвечают на каждый селектор, но пусты; `0400/1100/1804`
на `00/51` не отвечают вовсе. Серийников **самих сенсоров виженов** (перцепция
RD03, камеры) на `00/51` нет — они на канале GuidanceSDK (см. §6 и
`docs/vision-calibration.md`).

Версии суб-модулей тоньше версии аппарата: на двух бортах `16.01.0006` FC был
`11.00.0032` и `13.00.0002`, SoC — `10.00.4371` и `10.00.5393`. `[C]`

## 2. Что внутреннее (с хоста недостижимо) `[C]`

- **Монокуляр (тип 17)** — в манифесте модуля нет, на шине нет.
- **Перцепция — 4× RD03 mmWave:** `2400` FRONT / `2401` LEFT / `2402` RIGHT /
  `2403` UP (нет DOWN/BACK). Прошиваются через relay upgrade-center, на хост не
  отвечают, виден только их прогресс в пуше `00/42` при флеше.
- **`2405` ld04 — LIDAR / лазерный дальномер:** только flash-target.
- **Fisheye-сенсоры** — MIPI-CSI камеры в CV-SoC, не DUML-узлы.
- **Набор команд `0x0A` (mbino)** — протокол FC↔вижн, через USB не ходит.
- **Рантайм бинокуляра/fisheye** живёт **внутри Ambarella-блобов `0802`/`1502`**
  — отдельного модуля типа 17/18 в манифесте нет (`[C]` для отсутствия).

## 3. Firmware-модули вижена (манифест `16.01.0006`)

- `0103` IR_Sensor — тепловизор 640×512 (сборки IA640 / HK). `[C]`
- `0105` LCPU, `0106` «Laser» (имя модуля буквально `Laser` — расхождение с
  `roles.py`, см. открытые вопросы). `[c]`
- `0802` первичный Ambarella imaging/video SoC (~278 МиБ) = upgrade center. `[C]`
- `1502` второй Ambarella / CV-SoC (~344 МиБ, крупнейший модуль); кандидат —
  процессор омни/fisheye-вижена. `[c]`
- `2400`–`2403` RD03 ×4 (перцепция), `2405` ld04 (LIDAR). `[C]`

## 4. Бинокуляр `1804` и `03/ce`

`1804` на шине — помимо ответа на `00/01` — шлёт один пуш: **FLYC `03/ce`
«Push Forbid Data Infos»** (гео-забор / no-fly), ~2 Гц, 28 байт, **байт-в-байт
константа** в сессии и между сессиями, поле семантики непрозрачны, **без
координат и серийника**. `[C]` Почему именно `1804` (а не FC) его шлёт — не
объяснено. `[c]`

## 5. Как конфигурится (FC obstacle-параметры)

Настройки вижена/обхода препятствий — items config table 0 набора `0x03`,
читаются `params` без unlock (`03/E0`→`E1`→`E2`). Подтверждённое ядро:
`avoid_obstacle_limit_cfg.avoid_obstacle_enable`, `user_avoid_enable`,
`go_home.avoid_enable`, `mvo_cfg.mvo_func_en` и семейство
`avoid_obstacle_limit_cfg.{a_dec_max, v_fwd_max, v_bck_max, safe_dis, …}`. `[C]`
Большинство остальных ~55 obstacle-имён — device-only, смыслы кандидатные. `[c]`
Живая команда состояния обхода `03/0x53` (публичный битфилд) на USB **не
появляется**. `[C]`

## 6. Что достижимо для инвентаря

- **Можно (live):** версии (`00/01`) FC/SoC/gimbal/battery/бинокуляра; серийники
  `00/51` через `serial-scan` — **3 у `0803`** (сел. `0x01/0x02/0x04`) и серийник
  борта (FC сел. `0x04`); данные батареи (`0D/02`); obstacle-параметры (`params`).
- **Можно (offline):** полный инвентарь модулей из подписанного манифеста —
  **реальный способ перечислить перцепцию/вижн** (имена, размер, md5, роли).
- **Нельзя (по DUML):** прямой запрос/версия/серийник монокуляра, перцепции
  (RD03/лазер), fisheye, радара — хост им не шлёт ни кадра. Серийники самих
  сенсоров виженов по `00/51` не выходят; по экспортам `DJI_guidance.dll`
  (`get_serial_code`, `get_sonar_serial_code`, `save_cali_param`) они живут на
  канале **GuidanceSDK** (vision-bulk), не в DUML — см. `docs/vision-calibration.md`.

## Открытые вопросы

- `0106` в манифесте назван `Laser`, а `roles.py` гадает «камера/ISP» — не решено.
- `0106` «Laser» vs `2405` LIDAR — что из них дальномер подвеса, а что obstacle-LiDAR.
- Семантика 28 байт `03/ce` (4-байтовая LE-константа после заголовка) — opaque.
- ~~Полный энум селектора `00/51`~~ — **решено** (`serial-scan`, выше): `0803`
  отдаёт 3 серийника (сел. 0x01/0x02/0x04), FC — серийник борта (сел. 0x04).
- Серийники сенсоров виженов (перцепция RD03 ×4, камеры) — **не** на `00/51`;
  достать их (и/или запустить калибровку камеры) по каналу GuidanceSDK
  (`get_serial_code`) и как ввести борт в vision-режим — **в работе**.
- Точное внутреннее подключение fisheye/радара/лазера к CV-SoC — не наблюдаемо по DUML.
